## Fixes made in this audit

1. **Home page data (performance 55 → 86, LCP 9.5 s → 1.9 s).** The home
   strip fetched the five whole category files (~1.3 MB) just to show 9
   cards. Added `data/featured.json` (9 records, ~6 KB, generated by
   `scripts/generate-api-data.py`) and the home page now fetches only
   that plus the manifest.
2. **Browse preview preloading.** The card IntersectionObserver preloaded
   previews 600 px before they entered view; reduced to 200 px
   (browse performance 63 → 71). Off-screen previews are still unloaded.
3. **Cards are keyboard accessible.** Browse cards were `<article>` with
   a click handler only — not focusable. Now `tabindex="0"`, `role="link"`,
   an accessible name, and Enter/Space opens the preview. The global
   `:focus-visible` rule already gives a 2 px accent ring.
4. **Empty search state was unreachable.** `renderBatch` returned early
   when a batch was empty, before the "No elements match" code — so a
   search with zero results showed a blank grid. The empty check now runs
   first, and the count updates.
5. **Preview navigation race.** `renderPreview` had no generation guard:
   navigating away while its data was loading could let the stale preview
   overwrite the new page (same class of bug as the browse-category race
   fixed in the auto-fit work). Added a `navGen` counter; stale renders
   bail out.
6. **Message-listener leak.** `wirePreviewControls` added a new window
   `message` listener on every preview navigation. Now guarded so it is
   registered once.
7. **SEO / social.** Added Open Graph + Twitter Card meta (og:image is
   `assets/banner.png`, 1280×420), `sitemap.xml` (root + data files —
   a hash SPA has no other crawlable URLs), `robots.txt`, and a friendly
   static `404.html` for GitHub Pages. Favicon already existed.

## Known gaps and follow-ups

- **Browse performance (71).** The browse page loads all 11 category
  files (~2.2 MB) when the filter is "all" or a search is active, because
  it needs every element to search and filter. The fix is to drive the
  browse list from `data/index.min.json` (768 KB, add `author` to its
  entries) and load a category file only for the preview page. That is a
  bigger refactor of the browse data flow and is not done here — it is
  the main remaining performance lever.
- **No skip link.** Tab order reaches the grid after the top bar, the
  trigger chips, the tag select and the sidebar tree rows, and every
  card's live preview iframe is also tabbable, so keyboard navigation to
  the grid is long. A "Skip to results" control is the standard fix.
- **"Click" trigger has 0 elements** in the manifest, so the click
  autoplay path has nothing to exercise. Not a bug — just nothing to test.
- **Google Fonts is render-blocking** (JetBrains Mono stylesheet). It is
  only used for code; the fallback is system monospace. Deferring it
  would help first paint slightly.
- **app.js / style.css are unminified** (Lighthouse: ~12 KiB + ~3 KiB
  savings, ~33 KiB unused JS). Small; a build step would be needed to
  minify without breaking the injected driver string.

## Post-audit fix (21 Nov, commit 08c1acf) — blank card + still previews on mobile

Reported from the live site on a phone: the Afraid Donkey 40 card showed a
blank preview while the card below it (Afraid Eagle 38) rendered, and many
grid animations looked still.

Root cause: the browse `IntersectionObserver` watched only the `.preview`
box. A card whose preview had scrolled just off the top (name still
visible) had its iframe unloaded and looked blank. Reproduced at 390px
and confirmed the fix: the observer now watches the whole card, so the
preview stays loaded while any part of the card is on screen. Verified
with the preview 210px above the viewport and the name visible — the
iframe stays loaded.

Second cause: browse previews were created with autoplay off, so hover /
checked / click elements showed one frozen state. Grid previews now
autoplay for hover, active, auto-loop and static triggers (class pulse /
native CSS animation — verified a loader's pseudo-element transform
changes over time, and a hover button's sim class pulses). checked /
click / focus stay on their one-shot active state, so the driver never
steals the search box focus while the user types. Live iframes stay
bounded (4 at 390px after scrolling). Audit re-run after the fix: 27/28
(same single flaky wrong-id check).
